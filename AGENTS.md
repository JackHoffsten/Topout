## Branch naming

Name new branches `<type>/<short-kebab-case-description>`. Choose the type by the
purpose of the change: `feat`, `fix`, `refactor`, `docs`, `test`, `chore`, or `ci`.
For issue-specific work, include the issue number after the type, for example
`fix/42-progress-location-refresh`. For work spanning several issues, use a shared
description, for example `refactor/training-architecture`.

Use these type prefixes instead of the default `codex/` prefix. Preserve existing
branch names unless the user requests a rename.
