# Domain docs

## Before exploring

Read root GLOSSARY.md and relevant decisions under docs/adr/.
If GLOSSARY-MAP.md exists, follow its pointers to relevant glossaries
and context-specific ADRs.

Proceed silently when these files are absent. The domain-modeling
skill creates them when terms or decisions are resolved.

## Layout

Topout uses a single-context layout:

- GLOSSARY.md at the repository root
- docs/adr/ for architectural decisions

## Vocabulary and decisions

Use glossary terms when naming domain concepts in issues, proposals,
hypotheses, and tests. Note meaningful vocabulary gaps for
domain-modeling.

Explicitly identify any proposal that contradicts an existing ADR,
including the ADR reference and reason for reconsidering it.
